# Контекст проекта: Агрегатор сиделок для животных "Зоопортал"

## Стек технологий
* Бэкенд: Python, Flask
* База данных: SQLite + Flask-SQLAlchemy
* Авторизация: Flask-Login, Werkzeug (хеширование)
* Фронтенд: Чистый HTML/CSS (без фреймворков), шаблонизатор Jinja2 для динамического вывода данных

## Продуктовая логика (две связанные части)
Сайт держится на двух сущностях, и они должны «встречаться» в одном сценарии:

1. **Каталог ситтеров** — публичная часть, доступна без регистрации.
2. **Ветпаспорт питомца** — приватная часть, живёт в личном кабинете владельца.

Связка: владелец выбирает ситтера → передаёт ему карточку питомца → ситтер приходит подготовленным.
Поэтому на главной всегда есть переход «Заполнить ветпаспорт» (в кабинет, а для гостя — в регистрацию),
а в кабинете — обратный переход «Найти ситтера».

## Карта страниц

| Маршрут | Шаблон | Назначение |
|---|---|---|
| `/` | `index.html` | Лендинг + каталог. Порядок секций: hero → поиск → «как это работает» → каталог → стандарты → блок для ситтеров → консьерж |
| `/register`, `/login` | `register.html`, `login.html` | Авторизация, максимально короткая форма |

| `/delete_pet/<id>` | — | POST-удаление карточки (только своей) |
| `/contact` | — | POST-заявка консьержу с главной, отвечает flash-сообщением |

Якоря главной страницы: `#catalog`, `#how`, `#standards`, `#sitters`, `#contact`.
На них ссылаются шапка, подвал и внутренние CTA — при добавлении секции обновляйте и там, и там.

## Шаблоны: правила наследования
* Все страницы расширяют `templates/base.html` (`{% extends 'base.html' %}`).
* В `base.html` живут: `<head>`, шапка с навигацией, flash-сообщения, `<main>`, подвал, скрипт мобильного меню.
* В дочерних шаблонах переопределяются `{% block title %}`, `{% block content %}`, при необходимости — `{% block scripts %}`.
* **Нельзя** копировать шапку/подвал в новую страницу: расхождения между копиями — основная причина, по которой старая версия «расползалась» (разные якоря, разные email).
* Шапка зависит от авторизации: гостю — «Войти / Создать аккаунт», пользователю — «Мои питомцы» + email + «Выйти».

## Структура классов HTML/CSS
* При генерации или обновлении верстки строго опираться на существующие CSS-классы проекта (например: контейнеры `.container`, карточки `.sitter-card` / `.editorial-card`, кнопки `.btn`, `.btn-outline` и т.д.).
* Запрещено придумывать новые классы с нуля и использовать инлайн-стили (style="..."), если в этом нет крайней необходимости.
* Переиспользуемые блоки вместо новых сущностей:
  * `.sitter-card` — карточка ситтера и карточка питомца;
  * `.editorial-grid` / `.editorial-card` — «как это работает», «стандарты»;
  * `.empty-state` — пустое состояние (видимое — с классом `.is-visible`);
  * `.contact-details` / `.detail-item` — пары «подпись — значение» в карточках и кабинете;
  * `.field-group` / `.input-control` / `.form-row` / `.contact-form` — любые формы;
  * `.filter-group` — ряд кнопок-действий и фильтров.
* Служебные состояния: `.flash-success` / `.flash-error` (сообщения), `.tag-muted` (неактивный тег), `.btn.is-active` (выбранный фильтр).

## Модели базы данных (SQLAlchemy)

```python
from flask_sqlalchemy import SQLAlchemy
from flask_login import UserMixin

db = SQLAlchemy()

class User(db.Model, UserMixin):
    id = db.Column(db.Integer, primary_key=True)
    email = db.Column(db.String(120), unique=True, nullable=False)
    password_hash = db.Column(db.String(256), nullable=False)
    pets = db.relationship('PetPassport', backref='owner', lazy=True)

class PetPassport(db.Model):
    id = db.Column(db.Integer, primary_key=True)
    owner_id = db.Column(db.Integer, db.ForeignKey('user.id'), nullable=False)
    pet_name = db.Column(db.String(100), nullable=False)
    species = db.Column(db.String(50), nullable=False) # вид (собака, кот и т.д.)
    breed = db.Column(db.String(100)) # порода
    birth_date = db.Column(db.String(20)) # дата рождения
    vaccinations = db.Column(db.Text) # прививки
```

## Ближайшие шаги (что осталось за рамками текущей структуры)
* Каталог пока статичный (карточки в `index.html`) — вынести ситтеров в модель `Sitter` и фильтровать запросом, а не JS.
* Ветпаспорт хранит только отметку «вакцинирован» — добавить дату вакцинации, клинику и номер чипа (потребуется миграция: `db.create_all()` не меняет существующие таблицы).
* Согласие владельца на передачу карточки конкретному ситтеру — сейчас об этом только текст в интерфейсе.
* Заявки с форм (`/contact`) никуда не сохраняются: нужен обработчик писем или таблица обращений.
